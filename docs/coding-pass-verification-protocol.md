## The protocol (six rules)

1. **Record-grounded verification.** A spot-check verdict is valid ONLY against the item's full source record, never against the coding seat's rendering of it. Where multiple carriers exist, the design's carrier precedence applies, WITH ITS CONDITIONALS: the aggregate record is authoritative WHERE an admissible aggregate exists; where the aggregate is a stub, the paired findings file (flagged); where run.json is the sole aggregate carrier, run.json (flagged); where none exists, the named-substitute leg files (dedupe-checked) (the design's per-run alternative — exclude with the finding count disclosed — also stands); round files are attribution/adjudication input, never the counted finding source WHERE an admissible aggregate or paired source exists (docs/retrospective-eval-design.md, Unit of analysis) — the minimal span such that altering it flips the code is the DECISION SURFACE, and the check re-reads that surface in the record. This transplants psv's load-bearing invariant (a refuted/narrowed finding MUST cite a fetched-source quote, not model recall — skills/primary-source-verification/SKILL.md) to evaluation: the oracle is the record, not the reviewer. NO MATERIALIZABLE RECORD → the item is `unverifiable`: excluded from all asserted counts and disclosed in the output artifact. VOLATILE records (gitignored / regenerable trees) are marked record-volatile in the artifact even when verified, mirroring psv's volatile-source registry — a v1.2 REQUIREMENT not yet practiced: the calibration tree is itself volatile and carries no such marking, disclosed. RECORD CONTRADICTS THE CODE → the item is dropped from the asserted count AND reported as a refutation beside the agreement numbers (a refuted positive is signal about the PASS, not the item). psv's DOWNGRADE is kept; psv's human-escalation arms are NOT adopted in v1.2; adopt or reject each explicitly at next revision. The arms, per psv SKILL.md: K > 0 — unverifiable claims present. M = 0 — no admissible surface. They are disjoint: psv defines M = N+R+W+K, so M = 0 forces K = 0.
2. **Full-strata sampling.** Group = all items sharing one value of a declared dimension; the use's author declares dimensions before sampling. The spot-check sample must cover EVERY group on EACH declared dimension; a declared dimension or GROUP that proves uncoverable is recorded as declared-uncovered-disclosed per group in the artifact (not silently narrowed) (calibration dimensions: unit and seat/leg, disclosed as follows), per dimension:
   - unit: positive coverage 5 of 5 positive-producing units; the 5 zero-positive pool units are declared-uncovered-disclosed (not spot-checkable on positives; the token was RETROFITTED to the record 2026-09-15 — the cycle itself predates it); negative coverage: 3 negatives drawn from 3 distinct units, a global draw not per-unit; 2 record-verified negatives in 2 units after the lookup miss — disclosed.
   - seat/leg, per group: same 9 / hetero 2 attributable (both-group empty — no id-level pair matched); null 12 = declared-uncovered-disclosed (attribution unavailable); status recorded in the record's calibration_dimensions['seat/leg'] (rendered as a triad there — a token-grep will miss it; positive_leg_split carries the counts). Coverage is per-dimension marginal coverage, not the cross-product, which is unaffordable at scale. Within groups, bias toward HIGH-RISK items: shortest quotes, narrowest decision surfaces (rule 1's definition), borderline wording.
3. **Negative controls are mandatory.** Sampling only positives tests false-positive drift one way; sampled negatives test the other. Minimum as TARGET: the LARGER of (a) 3 negatives per 5 positives in the spot-check sample, scaled proportionally and rounded UP (4 → 3; 5 → 3; 10 → 6), and (b) the per-group floor — ≥1 negative per group with available negatives. The single calibration delivered 2 effective under v1.2's reading, below target, disclosed. A group with no available negatives has an unsatisfiable floor; disclosed in the artifact. The cycle's spot-check drew 3 negatives as a global draw. One of the three (PSVGM-N02) was a record lookup miss; under rule 1 as written it WOULD be unverifiable, counted as verified at the time — a calibration-era deviation — so the effective record-verified count is 2. Disclosed in the record. The per-group floor is a v1.2 STRENGTHENING, not yet practiced in any calibration cycle; treat it as the target for the next use, and disclose when a cycle falls short of it. Negatives are drawn from the CODED CANDIDATE LIST (the frame; recorded as a per-use parameter). A WOULD-BE-FLIP = a sampled negative that the second seat, or a record re-read, scores positive; flips found are REPORTED alongside the agreement numbers.
4. **Second-seat consistency re-run.** An independent fresh seat re-adjudicates a fixed subsample of the PRE-FILTERED CANDIDATE LIST (the frame; recorded as a per-use parameter if a different frame is chosen) (when no independent second seat exists, perform the re-run at rule 6's same-seat re-read tier and record the tier deviation) (calibration: every-5th, 20%; method recorded in the artifact). An `unverifiable` subsample item is excluded from the agreement and share denominators and disclosed; if the EFFECTIVE subsample is empty (all items unverifiable), assert NO agreement number, disclose the exclusions, and keep the tier and frame records. Read as if/else-if, in order: IF the subsample contains NO minority-class item → record share=0, skip the coefficient as degenerate, disclose the draw; ELSE IF minority share < 20% → report raw agreement AND a chance-corrected coefficient (a v1.2 REQUIREMENT not yet practiced — the calibration shipped raw only at 9.4% share, a disclosed gap); ELSE (share ≥ 20%) → raw agreement suffices, coefficient optional (trigger evaluated and recorded each cycle; kappa's interpretation grounding waits for a second cycle). Per-item disagreement is signal about ITEM difficulty, not seat quality, until a mechanism check (the seats read different record regions) proves otherwise. Ordering with rule 1: the rule-1 record re-read runs FIRST; only where the record is silent or ambiguous does this rule's difficulty attribution apply.
5. **Conservative resolution is ONE-DIRECTIONAL.** The bridge from rule 4: difficulty ⇒ uncertainty ⇒ excluded from the asserted count; "proven otherwise" means a mechanism check, NEVER a re-vote. Disputed positives are dropped; findings the second seat adds are NOT added back. The headline is a lower bound; BOTH raw and conservative counts are reported with their denominators. (Rationale: consumers of the measure inherit only what you assert — assert the floor.)
6. **Independence-tier disclosure.** The checker's independence is ranked: human-outside-the-loop > orchestrator (different context; same principal = the same orchestrating agent) > same-seat re-read. Model-family relatedness is an ORTHOGONAL axis — record it beside the tier (the calibration's two seats were same-family, disclosed in the record's second_seat_tier). Whichever tier performed the check is recorded verbatim in the output artifact; a weaker tier than the design promised is a disclosed deviation, never silently equivalent.

## Output-artifact minimum fields

The output artifact every rule discloses into MUST carry at least: the checker tier verbatim (rule 6); the sampling frames (rules 3 and 4); per-dimension and per-group coverage status with the declared-uncovered-disclosed token where applicable (rule 2); raw AND conservative counts with denominators (rule 5); refutations and flips found (rules 1 and 3); negative-control status — drawn/effective counts vs target, per-group floor satisfaction (rule 3); the source carrier used per item with its flag where the precedence chain applied (rule 1, incl. the per-run exclude decision); record-volatile markings (rule 1); unverifiable-item disclosures (rules 1 and 4); rule-4 outputs — agreement, coefficient status, trigger evaluation; model-family relatedness beside the tier (rule 6).

## Interface to existing workspace machinery

- Rule 1 ↔ psv's load-bearing invariant (`skills/primary-source-verification/SKILL.md`: refuted/narrowed MUST cite fetched text, never recall) — same epistemics, different oracle object (record vs fetched source), including the `unverifiable` downgrade.
- The protocol as a whole ↔ backlog C9's descent test (docs/external-reference-candidates.md C9): descent to a deterministic check needs BOTH proven recurrence AND economics — expected drip cost (instances re-found across rounds) exceeding the new gate's ~9+-file ripple (workspace rule 5). This protocol is a frame-layer codification; a dispute-heavy scenario is the recurrence half of that test.
- Rule 6 ↔ record-honesty discipline (workspace rule 3): deviations disclosed in the artifact, never in conversation only.
