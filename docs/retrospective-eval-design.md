# Retrospective evaluation design — solidforge evidence corpus

> Status: design draft for the retrospective analysis (phase C of the corpus work — after the ephemeral-evidence harvest, phase A, and the cross-project collection, phase B) of the harvested evidence corpus (`docs/papers/evidence-corpus/`, untracked/pre-scrub, 205 record JSONs / 1461 findings, harvested 2026-09-14). Motivation: `docs/papers/spec-gaming-orthogonal-axis.pub-readiness.md` names "no empirical evaluation" as the gap between position-paper tier and research-conference tier; the paper's residual empirical proposal — the §8.3 two-axis DEFENSE evaluation (the benchmark slot itself is already filled observationally/adversarially by SpecBench and ImpossibleBench; what stays open is whether heterogeneously decoupled oracles catch what same-source judges miss) — is prospective. This design covers the RETROSPECTIVE half the existing production records can honestly support. Pipeline: authored directly (all material in-context) + cross-source-review convergence, mirroring the `docs/external-reference-candidates.md` precedent.
> Non-goals: does NOT verdict the convergence loop's effectiveness versus alternatives (no control baseline exists — descriptive, not causal); does NOT replace the §8.3 prospective benchmark; outcome-axis conclusions stay human.

## Research questions

- RQ1 — multi-leg necessity: what fraction of findings would be LOST with a single leg? A retrospective ANALOGUE of the divergence observation named by pub-readiness F2 (paper §8 item 8) — not the §8-item-8 test itself (no known-gap ground truth; see Honest limits).
- RQ2 — fix-introduced defect frequency: how often are defects introduced by an EARLIER fix in the same run — a prior round's fix, or an earlier fix within the SAME round (the worked exemplar is same-round: the H1 mislabeling entered with the R1-5 rewording, both round-1 findings) — then caught within the loop? (The fresh-context CAUSAL claim — "caught only because reviewers are fresh" — is a counterfactual the corpus cannot carry; it is a non-goal, disclosed in Honest limits.)
- RQ3 — class-discovery dynamics: how do instances of one defect class distribute over rounds (the drip premise behind backlog C9 — the review-loop ladder discipline, `docs/external-reference-candidates.md`)?
- RQ4 — loop economics: rounds-to-convergence distribution, cap-hit / stalemate rates, new-blocker decay across rounds.

## Unit of analysis and corpus rules

- Unit = one RUN. Collapse key DIFFERS by layer: in `raw/solidforge-runs/` one run directory = one unit; in `raw/consumer-projects/` the unit is the run's record set — `<stem>.findings.json` pairs with `<stem>.run-record.json` as ONE unit (the diagnostics consumer's form — P2: four runs across eight files), and a directory can hold many independent runs (e.g. the WAF consumer's — P1 in the pseudonym map — plan-queues directory holds ten v0.4–v1.3 runs). A standalone findings file with no paired record AND no round key is an aggregate carrier of its run — EXCEPT leg aggregates (below), which are attribution cross-checks only; "paired record" = a stem-paired run-record (consumer layer) or a run-level aggregate (run-dir layer).
- **Authoritative finding source per run = the aggregate record** (record.json / convergence-record.json / csr-record / run-record). Where the unit's aggregate is a RUN-RECORD STUB (ring-level counts, no findings array), the stem-paired dot-form `<stem>.findings.json` — or a BARE paired `findings.json` (the eval-harness nesting form, where a run dir sits inside an eval directory; the run-record's directory is the unit) — is that unit's finding source (flagged). `run.json` is an aggregate-DUPLICATE kind: ingested only when the unit has no other aggregate (the prompt-content-spec case, where it is the only aggregate carrier), flagged when so ingested. A bare `findings.json` (no stem, no leg token — e.g. an eval bundle) is a unit finding carrier, never a leg input. A unit with NO admissible aggregate at all (e.g. psv-gate-dogfood — leg files only): either excluded with its finding count disclosed in every metric, or admitted via its leg files as a named substitute — decided per run, and the per-run decision list ships with the results. Round-level files (any file carrying a round key — `rN-*` / `roundN-*`, including `rN-findings.json`, `roundN-same-family*.json`, prior-context and dispositions forms) are NEVER counted as finding sources WHERE an admissible aggregate exists — they are attribution and adjudication INPUT (leg attribution from leg-separated files; qualification text from dispositions); where NO admissible aggregate exists, the named-substitute branch above makes the designated leg files the finding source (dedupe-checked). Prior-context/carry-forward files re-list earlier rounds' findings and aggregate records re-list all rounds; without this rule the same finding is counted 2–4×. LEG AGGREGATES (a run's full one-leg set, no round key — e.g. `same-leg-full-findings.json`) are attribution cross-checks only, never counted. A standalone aggregate record with no findings file is itself a one-record run unit (≥9 such in the consumer layer).
- Dispositions files therefore have TWO stated roles: excluded as units/finding sources, admissible as adjudication input (RQ1 attribution, RQ2 qualification). Both roles are deliberate, not a contradiction.
- Committed `docs/*.csr-record.json` files are a REFERENCE layer. Copy identity is by RUN, not filename — match on the record's `artifact` + findings-set hash (canonicalized finding objects, order-insensitive; verified on two byte-identical pairs AND one canonically-identical-but-not-byte-identical pair — prompt-content-spec's committed csr-record ≡ its run.json, 96/96 findings — a filename-keyed or byte-keyed read would double-count these runs). Ingest rule: ingest a committed record only when no corpus record matches on (artifact, findings-set hash); flag every ingested reference item.
- Non-unit JSONs (context only): eval/baseline/variant/plan-model files, evidence packets. `psv/coverage-record` kind = single-pass units: environment-key coverage analysis only, excluded from RQ1–RQ4.
- Exclusions with disclosed counts: parse-failures (3 known in the index); findings-shape nonconformance per record.
- Vocabulary normalization: SEVERITY-based exclusions from defect denominators (coverage-severity items; `[note-class]`-marked warnings AND `severity: "note"` findings — marker and severity forms appear across aggregate and round-file carriers, the exclusion is carrier-independent) and KIND-based buckets that do NOT exclude (kind `blind-spot` → its own counted class, not an exclusion; absent `kind` key → own bucket with the kind-less share of primary inputs reported). Severity `coverage_note` ≡ `coverage`. The normalization table WILL BE committed beside the metric (deliverable 2) and extended as new outliers appear.
- Survivorship disclosure: durable records underrepresent degraded/aborted runs; the ephemeral-evidence harvest (the 2026-09-14 corpus harvest's in-repo step — gitignored workspace run dirs) recovered part of the evidence layer (progress sidecars) but not unrecorded runs. Stated in every output.

## Metric definitions (numerator / denominator / exclusions)

- **Leg yield (RQ1)**: producing-leg attribution is by FILE ORIGIN, not id prefix — PRIMARY: a filename matcher pinned exactly. INPUTS (in precedence order — token forms FIRST, the suffix form applies ONLY to token-less basenames): `.json` files whose basename contains `hetero` (different-family leg) or `same` (same-family leg); else a basename ending with the hyphen token-less suffix `-findings.json` (the same-family round file — solidforge-runs layer). The consumer layer's dot-form `.findings.json` stem pairs are UNIT finding carriers, NOT leg-matcher inputs (they carry no leg). The corpus-assert fails loud on any CANDIDATE LEG-INPUT file fitting no input form (NEVER-INPUTS and unit finding carriers are excluded BEFORE the assert) AND on multi-form matches. NEVER-INPUTS (evaluated FIRST — a basename matching any never-input is excluded regardless of input-form matches): basenames containing `dispositions`, `prior-context`, or `prior-findings`, and the exact name `same-leg-full-findings.json` (a leg aggregate). A `roundN-` prefix is equivalent to `rN-`. The matcher is corpus-ASSERTED — run against every unit before computing, failing loud on any leg-findings file that fits no input form. SECONDARY (run-level only): aggregate per-round leg fields, spelling normalized per carrier kind — `same_source_findings`/`hetero_findings` (count fields) in convergence-record / record.json / csr-record carriers; `same_findings`/`hetero_findings` (per-round finding ARRAYS) in run.json carriers; any carrier using the prose-string forms (`same_family`/`hetero` keys carrying prose summaries — P4 is the live admissible exemplar; P3's prose forms exist only inside its parse-failed (excluded) records) and any unlisted spelling → disclosed cross-check miss, not a silent drop. Prefix forms (R\*, H\*, h\*, `bc*-dfr-*`, lowercase r\*, bare slugs) vary per run and are a cross-check only, NEVER the classifier. Expected computable N is SMALL — inclusion criterion: per-finding attribution exists where at least one leg-separated file survived (8 units known as of 2026-09-15: node-bin-adoption, web-claim-verifier, seam-tracer-proposal, csr-bc-seam-anchor, psv-gate-dogfood, prompt-content-spec, csr-coder-dispatch-fix, external-reference-candidates — the last two same-family-side only; the list is REGENERATED from the corpus at metric time and the computed N_runs reported). RQ1 is a small-N descriptive result. DEGRADED/ABSENT-LEG ROUNDS: a round in which a leg did not deliver (the corpus marks these: `hetero_degraded` flags — the only live per-round flag; `malformation` markers with NON-EMPTY values — e.g. csr-bc-seam-anchor r8/r9/r10- and csr-seam-tracer-proposal r1/r2-hetero-findings.json in leg files, hetero-stream-no-result in aggregate/prior-context carriers; web-claim leg files carry the key with an EMPTY value and do not count; no DEGRADED prose carrier exists in parseable records — the prose forms live only in rule quotations and parse-failed records) is flagged and its count disclosed per leg BEFORE computing shares; RQ2's per-leg skew gets the same treatment. Corpus-completeness assumption: the harvested set's completeness (read-only copy from the source trees) is an assumption behind RQ1's N, disclosed beside the survivorship note. Both-report pairs: match rule = same `kind` + overlapping location, LLM-adjudicated with ≥10% human spot-check (mirrors the RQ2 coding discipline); pairs count once in each leg and once in "both" (same-only + hetero-only + both = classifiable). Severity stratification: blocker and warning reported separately; coverage-severity items (honest disclosures, not defects) and `[note-class]`-marked warnings (advisory observations recorded into the warning stratum because the record schema has no note tier) are EXCLUDED from defect denominators. Report: same-only / hetero-only / both / unattributable, as counts AND shares.
- **Fix-introduced frequency (RQ2)**: a finding qualifies when its evidence or disposition names an earlier fix in the same run as the origin — a prior round's fix OR an earlier fix within the SAME round. Exemplar: `H1-c2-erosion-attribution` in the COMMITTED `docs/external-reference-candidates.csr-record.json` ("the mislabeling entered with the R1-5 rewording" — a same-round case, both round-1 findings) — the committed csr-records under docs/ are part of the reference layer (see unit rules), because run-dir evidence copies carry the source quotes but not the fix-introduced sentence. Identification is NOT mechanical — coding pass over finding evidence strings (LLM-assisted coding, human spot-check ≥10% of positives), inter-pass consistency re-run on a 20% subsample; disagreement → conservative non-count. Numerator: fix-introduced findings; denominator: all defect-severity findings in multi-round runs. Report per producing-leg (expect skew toward the leg that did not author the fix).
- **Drip curves (RQ3)**: class = the finding's `kind` field within one run — the class domain is the six finding kinds (contradiction / authority-chain-break / scope-creep / structural-gap / citation-error / coverage-gap) PLUS normalization-table buckets (e.g. blind-spot); sequence = count of new instances per round; report the distribution of "rounds spanned per class" and the share of classes that spanned >1 round. Censored at each run's final round. Exclusions per the normalization table (coverage-severity and note-class/note-severity items). This quantifies the drip premise behind backlog C9 (the review-loop ladder discipline, `docs/external-reference-candidates.md` C9).
- **Loop economics (RQ4)**: descriptive only — rounds, blockers-per-round, substantive_converged / stalemate / cap-hit rates. SCOPE: multi-round records only; run-record stubs (≈22 records whose key set is artifact_type / caveats / coverage / inner_ring / outer_ring / process_converged / rightness — no rounds, no steps field) contribute process_converged descriptives and are EXCLUDED from rates, disclosed. No causal comparison across eras.

## Confound discipline (C1 retrofit, operationalized)

- Annotation layer = corpus index v2: per-run environment block (provider, model, era) added BESIDE the records — originals never rewritten (the never-relabel rule binds retroaction).
- Reconstruction sources, in order: the run's progress sidecar (provider/model on the event surface); the hetero-leg files' own `providers`/`provider_runs` fields (5 of 9 run units have no sidecar — the leg files are the surviving carrier; provenance label `leg-file`); record-internal dates; provider-era boundaries derived at metric time from the wrappers' committed profile history — `skills/cross-source-review/infra/scripts/profiles/` and `skills/parallel-development/infra/scripts/profiles/` (two rule-7 lockstep copies; the era derivation asserts they agree on provider/model/_family fields — file bytes are NOT the criterion, one profile carries a sanctioned \_comment divergence) + ADR-anchored provider notes. Unreconstructable → `unknown` (era included), and every cross-run comparison reports reconstruction coverage % (runs with known environment / total).
- Model-era bucketing where reconstructable; comparisons that straddle buckets report per-bucket and overall.

## Scrub norms and placement

- Pseudonymization map (project → P1…Pn) lives OUTSIDE VERSION CONTROL (gitignored workspace/ and the untracked corpus README), never committed. THIS design doc uses it for consumer names (P1 = the WAF consumer; P2 = the diagnostics consumer; P3 = the adoption-ledger consumer; P4 = the KB consumer) — the doc is itself in the publishable set and must not carry pre-scrub business identifiers.
- Publishable set: aggregate statistics, metric tables, and fully scrubbed illustrative excerpts (business names, file paths, domain terms replaced). Raw corpus and the unscrubbed index stay untracked; the placement decision (untracked / scrub-commit / outside-repo) is settled by this design's first analysis output — recommendation: scrubbed index v2 + analysis results committable, raw never.

## Deliverables

1. Corpus index v2 — the ANNOTATION LAYER (the confound-discipline operationalization): per-run environment block (provider, model, era) with provenance labels (sidecar / leg-file / record-internal / era-derived / unknown); the producing step for every later coverage-% report.
2. `analysis/metrics.py` — deterministic metric computation over the corpus (leg yield, drip, economics; RQ2 pre-pass candidates); it ASSERTS aggregate-vs-round-files consistency per run and REPORTS discrepancies instead of trusting either side — separating "aggregate covers rounds with no surviving round file" (a round-file coverage gap; one known: prompt-content-spec's aggregate carries 54 hetero-leg findings across 9 rounds while only one hetero round file survived) from "aggregate repeats a round file" (duplication); and it asserts committed-record pair equality by findings-set hash at ingest.
3. RQ2 coding pass results + human spot-check record.
4. `docs/papers/retrospective-eval-results.md` — results with honest coverage notes (survivorship, reconstruction %, exclusions).
5. Paper integration draft — the retrospective section for `spec-gaming-orthogonal-axis.md` (or its revision), scrubbed.
6. The indexer's dedup arithmetic (per-run unique-finding counts) committed beside the normalization table, so the 1461 headline is recomputable from committed artifacts (naive per-file sums differ in BOTH directions — duplicate re-listing inflates, and the index leaves findings_total null on 94 entries (unit carriers, leg aggregates) deflating — the recomputation resolves both).

## Honest limits

- Findings are UNADJUDICATED reviewer claims: no mechanism in the corpus verifies a flagged defect is real. All counts are claim-counts, not confirmed-defect counts; blocker/warning strata are reported separately and coverage-severity disclosures are excluded from defect denominators.
- No baseline/control: single-pass-review comparison does not exist in the corpus — RQ1 answers "what a leg adds", not "what the loop beats"; and RQ1 observes divergence without ground truth, so it does not test the self-certification conjecture (paper §8 item 8).
- Heterogeneous models/providers/eras across months; mitigation is bucketing + disclosure, not elimination.
- Schema drift across skill versions (finding shapes AND leg-id conventions evolved); conformance exclusions shrink N — every metric reports its usable N, and RQ1's N is expected small (single-digit runs with per-finding leg attribution).
- RQ2's coding pass is LLM-assisted with human spot-checks; its kappa/consistency number ships with the result. RQ2 measures fix-introduced frequency only — the freshness counterfactual ("caught only because reviewers were fresh") is unmeasurable in this corpus and is a non-goal.
- Committed-record ingest correctness rests on the (artifact, findings-set-hash) identity rule; the rule is mechanical, but any record the hash fails to match enters as a flagged reference item, and the flag list ships with the results.
